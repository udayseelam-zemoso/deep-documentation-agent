# Day 8-10: Lexical outlines and responsibilities

Week 2, Days 8-10. Code lives in `com.deepdoc.understand`, on top of the Day 6-7 Java AST.

Day 6-7 opened **Java** files and wrote facts. Two things were still missing:

- a symbol list for JS, Python, Go, and the rest
- one sentence that says what a file is for

That sentence is what Week 3 will use as the opening line of a section.

## What we built

```
ranked files (DEEP + SUMMARY; LISTED still skipped)
        │
        ├── Java ──► JavaAstUnderstander     (unchanged)
        └── other ─► LexicalUnderstander     comment-stripped patterns
        │
        ▼
KnowledgeGraph          same unique-type uses edges as Day 6-7
        │
        ▼
ResponsibilityInferrer  doc comment → name heuristic → optional LLM (DEEP only)
```

DEEP vs SUMMARY still decides fact depth. It also decides whether the model is asked to rewrite the sentence.

| Level | Outline | Responsibility |
|---|---|---|
| **DEEP** | Java AST, or lexical symbols | doc comment, else heuristic, else optional LLM rewrite |
| **SUMMARY** | same outlines, no method facts | doc comment, else heuristic. No model call |
| **LISTED** | not outlined | none |

## Lexical outlines

JavaParser is a real AST. Doing that for every language means shipping a huge grammar and a binder, and an autonomous scan still does not have the project's classpath.

`LexicalUnderstander` reuses `SourceScanner`: comments and string literals are blanked (so `// export function gone()` is not a declaration), then a short pattern list picks up:

| Family | What we keep |
|---|---|
| JavaScript / TypeScript | `class`, `function`, `const name = () =>` |
| Python | top-level `class` and `def` |
| Go | `type Name struct/interface`, `func`, methods |
| Rust | `struct` / `enum` / `trait` / `fn` |
| everything else | a Java-like `class` / `interface` / method pattern |

The first `#`, `///`, or `*` doc line is kept as the file's comment, with the same `{@link}` cleanup Java uses.

This is a symbol list, not a second knowledge graph. Uses-edges still come from names Day 6-7 extracted. A lexical class can own a unique type name, so a mention of that name can still become an edge.

## The one sentence

`ResponsibilityInferrer` tries three sources, in order:

1. **The author's comment.** `OrderService`'s Javadoc "Creates an Order after validation." is already the sentence.
2. **A name heuristic** when there is no comment.
   - `OrdersController` or `@RestController` → "Handles HTTP requests for orders."
   - `OrderService` → "Implements application logic for order."
   - `OrderValidator` → "Validates order."
   - a plain `Order` → "Order class."
3. **An LLM rewrite, DEEP files only.** The draft above is sent as the prompt. The model must return one sentence about purpose, not implementation. SUMMARY files are not sent: a paragraph does not justify a call, and a 100k-line repo would otherwise rewrite hundreds of files.

`--no-llm`, `llm.enabled: false`, or a missing key skips step 3. HTTP errors, timeouts, and empty bodies also skip it and keep the draft. The scan still finishes.

The key is read from `llm.apiKeyEnv` (default `OPENAI_API_KEY`). It is not stored in `application.yml`, not passed on the command line, and not written into the request JSON that tests inspect. The client does not log the request body.

```yaml
llm:
  enabled: true
  provider: openai
  model: gpt-4o-mini
  maxTokens: 200          # one sentence
  apiKeyEnv: OPENAI_API_KEY
  baseUrl: https://api.openai.com/v1
  timeoutSeconds: 20
```

## What `analyze` prints

Under each DEEP and SUMMARY file, after the Day 6-7 types and facts:

```
responsibility (javadoc): Creates an Order after validation.
responsibility (heuristic): Handles HTTP requests for order.
```

The header also says how many files were Java AST vs lexical, and whether responsibilities came from `heuristic` or `openai`.
